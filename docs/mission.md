# Mission — fire-apps website

**What:** The external-facing website for the FIRE app suite: advertise the
apps, walk through features, and tell the story behind why each one exists.

**Who it's for:** Prospective users — people tracking mileage, business
expenses, rentals, and personal finances on the road to FIRE — plus TestFlight
volunteers.

**Why:** A single URL to point people to. Today the apps have no public web
presence; TestFlight recruiting and App Store discovery both need one.

**Done when (v1):**

- Landing page introducing the suite and the F·I·R·E letter system.
- One page (or section) per app: features, screenshots, story.
- Direct App Store download links + TestFlight invite links.
- Deployed on GitHub Pages at a URL that can later move to a custom domain.

**Requirements / constraints:**

- Static site, no backend, free hosting (GitHub Pages).
- Brand assets come from `brand/` — the site must use the same icon system
  and colors documented in `brand/DESIGN-RATIONALE.md`.
- Framework choice deliberately deferred to the site-build session.
